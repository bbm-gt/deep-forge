# Learning Workflow — 子 Agent 执行

此文件在子 Agent 启动时读入，与 SKILL.md 和 strategy-format.md 一起构成子 Agent 的完整规则。

## 子 Agent 输入

- 本文件 + `{baseDir}/references/strategy-format.md`（规则）
- workspace 中已有的 strategy-memory.md（如存在——作为累积起点）
- 用户指定的文章路径或粘贴内容

## 执行步骤

### 1. 递增计数器

读取 workspace strategy-memory.md 顶部 `已处理文章总数` 和 `当前轮次`。本轮结束后：总数 += 本轮处理篇数，轮次 +1。

如 workspace 尚无 strategy-memory.md，按 strategy-format.md 中的模板创建，计数器从 0 开始。

### 2. 逐篇分析

对每篇文章：

**a. 判定文章类型**。参考 strategy-format.md 中的类型定义。如不属于已有类型，新增。

**b. 成功归因**。判断文章效果归因于什么。只提取归因于"内容结构"和"表达策略"的传播动作。归因于"作者IP""热点事件""平台红利"的部分，标注"不可复制，不进入策略提取"。

**c. 提取传播动作**。逐段分析作者在做什么。每个动作回答：
- 想对读者产生什么效果？
- 怎么做到的？（可引用原文，必须解释为什么有效）
- 什么条件下适用？

**d. 提炼为策略 + 去重**。对照已有策略库的「功能」字段：
- 功能相同 → 追加执行手法，验证+1，类型追加，检查升级
- 功能不同 → 新增，默认 🟢

**e. 记录反模式**。如果文章中有明显写作问题（空壳预告、过度推销、AI味表达），追加到策略库的「已知反模式」表。

### 3. 检查升级

遍历所有策略，读取元数据行的验证次数和类型数：

```
🟢 → 🟡：验证 ≥ 3 且 类型 ≥ 2  或  验证 ≥ 5
🟡 → 🔴：验证 ≥ 8 且 类型 ≥ 4
```

### 4. 检查降级

每处理完 20 篇文章后遍历：最近验证轮次距今 > 20 → 降一级。

### 5. 更新匹配表

每次策略层级变动后，更新「类型→策略匹配表」。每种文章类型列出其匹配的 🔴 和 🟡 策略。

### 6. 写入 workspace

将更新后的 strategy-memory.md 写入 `~/.openclaw/workspace/deep-forge/strategy-memory.md`。

### 7. 输出学习报告

```
本批学习报告（R轮次）：
- 处理：[N] 篇文章
- 新增策略：[N] 条（名称 + 🟢）
- 验证已有：[N] 条（名称 + 验证次数）
- 升级：[N] 条（X🟢→🟡 / Y🟡→🔴）
- 降级：[N] 条（如有）
- 新增反模式：[N] 条（如有）
- 策略库：[N] 条（核心X/模式Y/情境Z）
- 累计：[N] 篇
```

## 关键规则

- 本文无可迁移策略时如实汇报——"效果主要归因于作者IP/热点事件，内容结构和表达策略无独特方法论"
- 常见错误字段新策略填"待观察"，只在后续验证中实际观察到用错时才追加
- 不强行编造策略
